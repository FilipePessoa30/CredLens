## [Unreleased] - Release Candidate Acceptance Remediation (Phase 10B) - 2026-08-02

### Fixed — a real, evidenced gap in RC1's own acceptance criteria

`RC_1.0.0rc1_bc33e939` was declared `release_candidate_ready_with_limitations` with real coverage at 94% and a real `scenario_detection_rate` of 0.5 - `credlens.release.manifest.decide_readiness` never read a coverage number or a detection report at all, so neither could ever become a blocker. See `reports/release/release_errata.json` (append-only, RC1's original decision is preserved, never deleted).

- **Monitoring detection defect found and fixed**: `credlens.monitoring.data_quality`/`subgroup` computed `missingness_rate`/`domain_violation_rate`/`range_violation_rate`/subgroup composition correctly on the RAW batch (already in the right pipeline position, before imputation) since Phase 9/10, but nothing ever turned them into an `Alert` - `missingness_drift`/`out_of_domain_codes`/`feature_range_violation`/`prevalence_drift`/`subgroup_composition_shift` could never be detected. Fixed by wiring 3 new alert categories (`data_quality`, `target_distribution_drift`, `subgroup_composition_drift`) into `credlens.monitoring.runner`, each with its own calibration (fixed cutoffs for `data_quality` - its reference null is a genuine zero-variance point mass on this clean benchmark; bootstrap-calibrated for the other two). Real result: `scenario_detection_rate` 0.5 → **1.0**.
- **Two additional real bugs found and fixed during this work**: (1) `credlens.monitoring.subgroup.compute_subgroup_monitoring` was being called on batches that only ever carried raw `X2`/`X3`/`X4`/`X5` columns, never labeled `sex`/`education`/`marriage`/`age_bucket` - every real monitoring run's subgroup diagnostics had been silently empty since Phase 9; (2) the `feature_range_violation` scenario's `impossible_bill_multiplier` was not guaranteed to exceed the input contract's monetary sanity bound for every random row sample - now floored deterministically.
- **New, evidenced, staleness-checked release gates**: `credlens.release.coverage_gate` (`credlens release measure-coverage` reads a real `coverage.json`, stamps it with a source-snapshot fingerprint) and `credlens.release.monitoring_gate` (reads persisted `monitor evaluate-detection`/`evaluate-false-alerts` evidence) - both wired into `credlens release validate` as real, evidenced, staleness-aware blocking checks, never a hand-typed number.
- **`credlens.release.source_snapshot`** (new): a content-based fingerprint over every git-tracked file (not just `git rev-parse HEAD`, which is blind to uncommitted changes). Found and fixed a real self-reference bug of its own: the evidence files this same mechanism produces (`coverage_snapshot.json`, `detection_evaluation.json`, `false_alert_study.json`, `release_manifest.json`, `sbom.cyclonedx.json`) are themselves tracked, so writing any one of them shifted the fingerprint the others had just stamped themselves with - excluded from the digest (evidence *about* the code, never the code itself).
- **Dependency license classification** (`credlens.release.licenses`): direct vs. transitive, tagged by role (`runtime`/`warehouse`/`analysis`/`dashboard`/`modeling`/`notebook`/`dev`). Found and fixed a real detection gap: several well-known permissively-licensed packages (numpy 2.x, pydantic 2.x, scikit-learn, mypy, ruff) ship only a PEP 639 `License-Expression` (SPDX) field, no legacy `License ::` classifier - the original classifier-only check showed them as "unknown". Real result: 63 → 3 unknown licenses (197 total, 26 direct, 0 copyleft).
- **`credlens release errata`** (new): append-only log of corrections to a previously-emitted readiness decision.
- Sensitivity analysis (`run_sensitivity_analysis`): real execution across weak/moderate/strong magnitudes for 6 perturbation types - `strong` (the documented canonical magnitude) reaches the 90% detection floor for every type; weaker magnitudes are not required to, and empirically do not always.
- Deleted confirmed-dead code found along the way: `credlens.model_validation.provenance` (never imported anywhere) and two unused helper functions in `credlens.monitoring.calibration_study`.
- ~140 new/updated tests across release-gate, monitoring, and dashboard-page test files.

## [0.10.0] - 2026-07-28

### Added — Independent Model Validation, Monitoring Simulation and Model Risk Governance (Phase 9)

- **Gate zero (repository safety)**: read-only investigation confirmed no versioned git hooks, no `.vscode/` tasks, CI has `contents: read` only, and no `git commit`/`git push`/`autoCommit` pattern anywhere in the repo. HEAD matched `origin/master` at session start and throughout.
- **Independent recomputation, never a copy of the Phase 8 report** (`credlens.model_validation.recomputation`/`discrimination`/`calibration`/`thresholds`/`stability`): ROC-AUC via a rank-sum (Mann-Whitney U) estimator, PR-AUC via a manual step-function accumulation, KS via empirical-CDF separation, Brier/log-loss via plain reductions, calibration slope/intercept via `scipy.optimize.minimize` on a hand-written negative log-likelihood - all independent of `credlens.modeling.evaluation`'s `sklearn`-based implementation. All discrimination/calibration/stability metrics reproduced within a 0.0005 absolute tolerance; operating-point recall/precision needed a separately documented, looser 0.003 tolerance (tie-breaking/interpolation differences between two legitimate but different threshold-selection algorithms - not a bug).
- **Permutation-based negative control replaces the Phase 8 fixed-band shuffle check** (`credlens.model_validation.negative_controls`): 100 independent target permutations (10 for CI), each refit on train and scored on validation. Real result: empirical p-value 0.0099 (≤ alpha 0.01), permutation-null mean ROC-AUC 0.4907 (within 0.05 of random) → **passed**. The old single-shuffle check's fixed ±0.12 band is mathematically unable to reach significance below 99 permutations - documented, not silently ignored, in the CI smoke path.
- **Multicollinearity audit** (`credlens.model_validation.collinearity`/`coefficient_audit`): VIF, correlation matrix, condition number, bootstrap/CV/regularization-sensitivity coefficient-sign stability. Real finding: `total_bill_amount`/`avg_bill_amount` and `total_payment_amount`/`avg_payment_amount` are perfectly collinear (infinite VIF, exact linear multiples); `months_delinquent_count` (VIF 56.83) and `consecutive_months_delinquent` (VIF 52.80) are classified `redundant` - their reason-code language no longer implies a protective causal effect ("This feature reduced the fitted model score for this record; this is not evidence of a protective causal effect.").
- **Corrected subgroup gap definitions** (`credlens.model_validation.subgroup_validation`): `absolute_gap = max - min` computed only across `adequate` (n≥100) groups, `reference_gap` against the largest-n group, both independently recomputed from raw confusion counts. Real correction: Phase 8's reported "max TPR gap = 0.3323" was `university`'s own true-positive rate, picked as the maximum only because the minimum came from a `limited`-sample group (`undocumented_code`, n=56, ~4 actual positives). The corrected, adequate-groups-only TPR gap is **0.0657** (`graduate_school` vs. `university`) - reported alongside `absolute_gap_including_limited` (0.3323) so the correction itself is visible, not silently applied.
- **HistGradientBoosting formalized as a registered `challenger`** (`credlens.model_validation.challenger_review`, never `candidate`/`production`) and a real candidate/challenger Pareto comparison: challenger PR-AUC 0.5620 vs. candidate 0.5019, ROC-AUC 0.7801 vs. 0.7451, Brier 0.1344 vs. 0.1426, calibration slope 0.9915 vs. 0.9475, split-stability stdev 0.0076 vs. 0.0088, robustness degradation 0.1779 vs. 0.1886, artifact size 211 KB vs. 4.5 KB, scoring latency ~10.6ms vs. ~3.0ms per test batch - a genuine multi-axis trade-off, no forced single winner.
- **Reduced logistic regression built where the audit justified it** (`credlens.model_validation.reporting.build_reduced_experiment`): iterative VIF elimination (threshold 10.0) on the SAME locked split, a new experiment ID, `EXP_behavioral_default_v1` fully preserved.
- **Input contract gate** (`credlens.modeling.input_contract`): `strict` mode rejects a batch-level schema violation outright and quarantines row-level violations (duplicate ID, non-finite value, out-of-domain delinquency code, an impossible monetary range) to a local CSV; `audit` mode never blocks, only profiles. Turns the Phase 8 robustness finding (~0.169 PR-AUC degradation under an unseen delinquency code) into an enforced gate.
- **14 independent validation gates and a real decision** (`credlens.model_validation.decision`): dataset/split integrity, leakage, negative controls, discrimination, calibration, stability, coefficient stability, subgroup audit, robustness, input contract, artifact integrity, reproducibility, documentation. Official result for `MODEL_behavioral_default_v1`: **`validation_passed_with_limitations`** - all 13 blocking gates passed; the non-blocking `coefficient_stability` gate raised the multicollinearity finding above as a documented limitation, never a rejection.
- **Explicit model lifecycle** (`credlens.model_validation.lifecycle`): `experiment`/`candidate`/`challenger`/`validation_passed`/`validation_passed_with_limitations`/`validation_failed`/`retired` - append-only transition history; `production`/`deployed`/`automatically_promoted` are hard-refused, not merely undocumented.
- **Monitoring simulation on a historical public benchmark** (`credlens.monitoring`, never a real production monitoring system): a reference built from train+validation only (never the locked test set); 12 simulated batches built by partitioning the locked test set into 12 non-overlapping, ID-ordered 500-row slices, each perturbed per its own scenario (`baseline_like`/`missingness_drift`/`utilization_shift`/`payment_reduction`/`delinquency_worsening`/`out_of_domain_codes`/`feature_range_violation`/`prevalence_drift`/`score_distribution_shift`/`subgroup_composition_shift`/`label_delay`/`corrupted_schema`).
- **Feature drift beyond PSI** (`credlens.monitoring.drift`): PSI, KS, Wasserstein distance, Jensen-Shannon divergence, mean/median/variance/quantile shift, missingness delta - per feature, per batch.
- **Locally calibrated alert thresholds** (`credlens.monitoring.thresholds`): `review`/`material_deviation` cutoffs derived from the reference's OWN bootstrap resampling (95th/99.5th percentile of a null "batch-vs-reference" distribution) - never a copied market-generic PSI/KS band. Real run: 81 alerts across 12 batches, 1 batch (`corrupted_schema`) correctly `blocked_input`; false-alert rate on the unperturbed `baseline_like` batch measured at **0.1429** (3 of 21 checks).
- **Local, structured alerts only** (`credlens.monitoring.alerts`): no email/Slack/webhook transport exists anywhere in this codebase; every alert carries a recommended diagnostic action, never an automated remediation.
- **New CLI subcommands**: `credlens model {validate-independent,audit-collinearity,audit-negative-controls,compare-candidates,register-challenger}` and `credlens monitor {create-reference,simulate-batches,run,status,alerts,report,validate}`.
- **Model Monitoring Lab - the 10th dashboard page** (`dashboard/pages/10_Model_Monitoring_Lab.py`): data quality, feature-drift heatmap, PSI/KS/Wasserstein per feature, score distribution, risk-band shift, performance/calibration over batch sequence, subgroup composition/gaps, an alert timeline, the validation decision/gates, and the candidate/challenger trade-off - reads exclusively from `reports/monitoring/`/`reports/model_validation/`, never rescoring anything.
- **No new dependency**: `credlens.model_validation`/`credlens.monitoring` reuse the existing `modeling`/`analysis` extras (`scikit-learn`, `scipy`, `matplotlib`) only.
- ~200 new tests across 12 new test files (model_validation, input_contract, monitoring, CLI, dashboard).

## [0.9.0] - 2026-07-27

### Added — Interpretable Behavioral Credit Risk Modeling on the real UCI benchmark (Phase 8)

- **Problem framed as a behavioral early-warning model, never an origination score** (`config/modeling/behavioral_default.yml`, versioned target contract): reuses Phase 3's own `docs/target_and_leakage_audit.md` finding that 18 of 23 UCI predictors only exist because the account already has 6 months of history - "Behavioral early-warning model for next-month default" / "Modelo comportamental de alerta antecipado para inadimplência no mês seguinte", explicitly never an origination/credit-granting score, a regulatory PD model, or production-ready. Loaded strictly from the already-acquired, hash-verified manifest entry (`credlens.modeling.data`) - never re-downloaded.
- **Feature governance** (`config/modeling/feature_registry.yml`, versioned): 18 interpretable engineered behavioral features (delinquency/bill/payment aggregates - `credlens.modeling.features.engineer_features`, deterministic, safe-divided, always float64, manually-worked-example-tested) with an explicit status per raw/engineered column (`allowed`/`engineered_allowed`/`excluded_sensitive`/`excluded_identifier`/`excluded_target`). SEX/EDUCATION/MARRIAGE/AGE are `excluded_sensitive` by construction - audit-only, never a training feature.
- **Leakage prevention** (`credlens.modeling.leakage`): a static allowlist built directly from the feature registry (raises if target/ID/a sensitive column reaches a training frame) plus 5 functional negative controls that actually re-fit and measure (`credlens.modeling.reporting.run_negative_controls`): reject a direct target column, reject a renamed target copy, detect a near-perfect injected leak (ROC-AUC ≈1.0), a shuffled-target fit scores near-random (a symmetric ±0.12-of-0.5 band, not a one-sided upper bound - an asymmetric check was a real bug this phase's own tests caught, since it would have waved through a strongly *inverted* fit as "passing"), an ID-only model carries no signal.
- **Reproducible split** (`credlens.modeling.splitting`): stratified 60/20/20, seed-controlled, the test partition locked by an ID-keyed CSV table (not re-derivation alone) the moment it is created - no out-of-time split invented where the source has no real time dimension.
- **Four required model levels** (`credlens.modeling.baselines`/`training`/`tuning`): `DummyClassifier` (prior), a transparent single-feature isotonic rule on `max_delinquency_status` (monotonic by construction), a tuned logistic regression (the main interpretable candidate - `C` grid of 4, `StratifiedKFold(5)`, `average_precision`-scored), and a `HistGradientBoostingClassifier` challenger (2×2 grid, `StratifiedKFold(3)`) - every fit passes through one leakage-checked entry point (`fit_model`), `n_jobs=1` throughout, no nested parallelism.
- **Calibration** (`credlens.modeling.calibration`): compares uncalibrated / sigmoid / isotonic (skipped below a minimum positive-count) on validation only; the uncalibrated model was kept for the official candidate since no method improved Brier consistently - a real, reported "no improvement" outcome, not forced.
- **Full metrics suite grouped by kind** (`credlens.modeling.evaluation`): prevalence; discrimination (ROC-AUC, PR-AUC, KS); calibration (Brier, log loss, calibration slope/intercept, ECE); threshold-dependent (precision/recall/specificity/F1/balanced accuracy/confusion matrix); ranking (decile table - lift, cumulative gains, event rate, capture rate) - "accuracy" is never reported alone.
- **Illustrative operating points, never a profit-optimized threshold** (`credlens.modeling.thresholds`): top 5/10/20% and ~50/70/80% recall, always defined on validation and only evaluated on the locked test set, explicitly labeled "Illustrative review-capacity scenario".
- **Uncertainty and stability** (`credlens.modeling.uncertainty`): a 1,000-resample stratified bootstrap on the test set (ROC-AUC/PR-AUC/Brier/KS/recall+precision at the top-10% point, with percentiles/seed/method recorded) and a 5-fresh-seed split-stability sweep (each seed's own official test set, never reusing the registered experiment's locked test) - labeled "Resampling variability on this benchmark's test set - not generalization to any real institution", mirroring Phase 7's DGP-variability posture.
- **Interpretability** (`credlens.modeling.interpretability`): logistic coefficients/odds ratios (standardized space), permutation importance (validation-only), partial dependence (association, never causation), and pseudonymized (`CASE-<hash>`) local reason codes for 7 representative cases (TP/TN/FP/FN/high/medium/low risk) that structurally cannot reference a sensitive attribute. SHAP deliberately not added as a dependency - permutation importance + partial dependence cover the same need without a new, heavier dependency; documented, not silently skipped.
- **Post-hoc subgroup diagnostics** (`credlens.modeling.subgroup_audit`, section titled "Fairness and subgroup diagnostics - not a compliance assessment"): SEX/EDUCATION/MARRIAGE/AGE-bucket joined to predictions only here, strictly after scoring, one fixed threshold for every group, reusing Phase 7's `insufficient`/`limited`/`adequate` sample policy so a small group is never ranked or used to drive a reported gap.
- **Robustness under 9 controlled perturbations** (`credlens.modeling.robustness`): additional missingness (genuinely exercises the pipeline's imputer - the real UCI file has zero missing values), outliers, utilization shift, delinquency worsening, payment shrink, two prevalence-drift resamplings, Gaussian noise, and an out-of-domain delinquency code - technical robustness, never a real-crisis forecast.
- **Negative controls, experiment registry, model candidate registry, and explicit promotion gates** (`credlens.modeling.registry`): a compact, versioned JSON experiment record (dataset/split hashes, dependency versions, full metrics, no external service) and a `candidate` status (never `production`, never auto-promoted to `champion`) gated on 8 independent checks - beats Dummy and the simple rule on PR-AUC, meets a minimum ROC-AUC, no leakage detected, calibration considered, stable across split seeds, subgroup audit completed, artifact schema-validated. AUC alone never decides eligibility. A tampered `.joblib` artifact is rejected by hash before deserialization (a real bug this phase's own tests found and fixed: the model manifest's `input_schema` key order was being scrambled by `json.dumps(..., sort_keys=True)`, silently desynchronizing it from the fitted pipeline's actual feature order - scoring code now always uses the canonical `FEATURE_COLUMNS` order, never a manifest's dict-iteration order).
- **Batch scoring only** (`credlens.modeling.registry.score_batch`): pseudonymous record ID, predicted probability, a risk band derived from validation-set quantiles (never a regulatory threshold), model version, timestamp, schema version - never an approve/reject decision, a recommended limit/price, or an explanation touching a sensitive attribute.
- **`credlens model` CLI group** (13 subcommands): `data-audit`, `validate-features`, `create-split`, `train`, `evaluate`, `compare`, `explain`, `audit-groups`, `stress-test`, `register`, `validate`, `predict-batch`, `report` - a genuinely staged pipeline, each stage persisting exactly what the next needs to disk, so each CLI invocation is a fresh, independent process.
- **Model Lab - the 9th dashboard page** (`dashboard/pages/9_Model_Lab.py`, `credlens.dashboard.model_lab`/`model_charts`): provenance "Historical public benchmark - UCI, Taiwan, 2005", a persistent warning that it is not connected to the synthetic portfolio. 9 tabs: Overview, Champion/Challenger, Discrimination & Ranking, Calibration, Capacity Simulator (snaps to precomputed operating points only, never a live-recomputed threshold), Interpretability, Subgroup Diagnostics, Robustness & Stability, Model Card - every number read from tables `credlens model evaluate/explain/audit-groups/stress-test` already wrote, nothing recomputed in the UI.
