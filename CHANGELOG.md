# Changelog

All notable changes to this project are documented in this file. Format loosely follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [0.5.0] - 2026-07-25

### Added — Performance, counterfactual scenarios, and common random numbers phase (4B)

- **Performance**: profiled (cProfile + coarse `time.perf_counter` checkpoints) the `sample`-scale generator (re-measured at 8.484s on this machine with the unmodified Phase 4A code, not the ~57.3s figure Phase 4A's own report cited under different machine conditions) and applied 4 verified optimizations - bulk `states` construction in `payments.py` (was thousands of separate `groupby`+`to_dict` calls), vectorized canonical table hashing in `manifest.py` (was `DataFrame.apply(axis=1)`), manual month arithmetic in `schedules.py` (verified equivalent to `pd.DateOffset` across 200,000 randomized cases), and head-index installment pruning in `payments.py`. Result: **8.484s → 3.734s (~2.27x)**, `global_content_hash` preserved exactly at both `smoke` and `sample` scale. Two real bugs were found and fixed while doing this (a numpy fixed-width-string NUL-stripping quirk in the hash function, and a pre-existing `next_due_date` inclusive-boundary quirk that a naive optimization would have silently changed) - see `docs/performance_optimization.md`.
- **Common random numbers**: `policy_expansion`, `policy_tightening`, `macroeconomic_stress`, and `collections_change` now share byte-identical `customers`/`application_features`/`fairness_attributes` (and `applications`, except `status`) with `baseline` for the same seed - `credlens.generation.config.assert_crn_compatible` enforces this before generation, `credlens.generation.orchestrator.generate_scenario` reuses baseline's own id-hash prefix for population-affecting ids. Two real bugs fixed to make this actually hold: scenario-specific id prefixes broke cross-scenario id comparability, and an unrelated config-schema addition (`macro_shock`) was churning every scenario's config hash. See `docs/common_random_numbers.md`.
- **5 newly-executable scenarios** (`credlens.generation.config.EXECUTABLE_SCENARIOS`, up from `baseline` only): `policy_expansion`/`policy_tightening` (a single relaxed/tightened `policy.approval_score_cutoff`, proven superset/subset of baseline's approved set), `macroeconomic_stress` (a dated payment-behavior shock, pre-shock payments proven byte-identical to baseline, post-shock DPD90+ increase confirmed in 10/10 Monte Carlo seeds), `collections_change` (intensified collections/cure/recovery parameters, config-only so pre-eligibility payment behavior is provably unaffected), and `contract_coverage` (a small, deterministic, deliberately extreme-parameter test fixture forcing 12 of 13 target rare states in under a second - the one gap, delinquency relapse, is an architectural limitation of the current cure mechanism, documented with a concrete proposed fix). `data_quality_incident` remains without an executable generation config. See `docs/counterfactual_scenarios.md` and `docs/synthetic_calibration.md`.
- **`src/credlens/generation/` additions**: `suite` (`generate_suite`/`load_suite_manifest` - a baseline run plus every CRN scenario run, tied together by a suite manifest recording config diffs, population hashes, and directional checks), `montecarlo` (`run_monte_carlo` - multi-seed delta aggregation with mean/stdev/quantiles/fraction-in-expected-direction), `comparison` (`compute_metrics`/`compare_metrics` - aggregate technical metrics per run), `quarantine` (5 controlled data-quality incidents - duplicate PK, orphan FK, invalid domain, incoherent snapshot, impossible date - each verified to actually fail strict validation with its documented error code before being quarantined under `data/quarantine/`, never `data/synthetic/`), `feature_allowlist` (a versioned, explicitly-enforced allowlist of the 3 columns the decision score may read from `application_features`), and `profiling` (`credlens synthetic profile`'s two-pass clean-timing + cProfile support).
- New CLI commands, all Phase 4A commands preserved: `credlens synthetic generate-suite --scale --seed [--force]`, `credlens synthetic compare --baseline --candidate`, `credlens synthetic validate-suite --suite-id`, `credlens synthetic monte-carlo --scenario --scale --seeds`, `credlens synthetic profile --scale --seed [--scenario]`.
- `generation_runs` contract moved to version 3: `scenario` domain gained `contract_coverage`, `status` domain gained `quarantined_expected_failure`, and 2 new nullable columns (`suite_id`, `parent_run_id`) for suite tracking. No other contract or business rule changed - Phase 4B's quarantine incidents reuse 5 existing business-rule error codes (`PK_DUPLICATE`, `FK_ORPHAN`, `DOMAIN_VIOLATION`, `SNAPSHOT_AFTER_TERMINAL_STATUS`, `DECISION_BEFORE_SUBMISSION`) rather than adding new ones.
- 44 new tests (568 total) covering CRN, superset/subset invariants, pre/post-shock identity and direction, collections pre-eligibility identity, `contract_coverage`'s state coverage, all 5 quarantine incidents (including an incident that fails to produce its own claimed error), suite generation, Monte Carlo aggregation, comparison metrics, truth-layer functional/metamorphic isolation (static import check, signature check, allowlist tests, and a metamorphic test proving decisions are unaffected by an extreme truth-layer perturbation), and CLI smoke tests for every new command.
- New documentation: `docs/performance_optimization.md`, `docs/common_random_numbers.md`, `docs/counterfactual_scenarios.md`, `docs/synthetic_calibration.md`, `docs/data_quality_incident.md`; updated `docs/synthetic_generation_implementation.md`, `docs/assumptions_and_limitations.md`, `docs/roadmap.md`, `docs/business_rules.md`, `docs/data_contracts.md`, `docs/fairness_data_design.md`, `docs/architecture.md`, both READMEs.
- New reports: `reports/synthetic_validation/{performance_baseline,performance_optimized,scenario_suite_summary,directional_tests,monte_carlo_summary,contract_coverage}.json`, `reports/synthetic_validation/suites/SUITE_smoke_2026.json`, and a `README.md` indexing all of them.
- No new dependencies - built entirely on numpy/pandas/pydantic/pyarrow (already present) plus the Python standard library.

### Explicitly not included in this phase

A `portfolio`-scale (50,000 customer) run's outcome is reported honestly in this phase's final report rather than assumed; a mid-period `policy_versions` switch (the richer blueprint design for `policy_expansion`/`policy_tightening`); a "contacted → cure boost" mechanism keyed on individual collection contacts; any scenario combining two interventions at once; true delinquency relapse in `contract_coverage` (architectural gap, documented); a CLI command for the quarantine flow; a warehouse, dbt, SQL analytics, a predictive/trained model, a dashboard, a business recommendation, and no commits or pushes. See `docs/roadmap.md`.

## [0.4.0] - 2026-07-24

### Added — Baseline deterministic synthetic-portfolio generator phase (4A)

- `src/credlens/generation/` package: `config` (Pydantic-validated executable configuration, `config/synthetic/baseline.generation.yaml`), `rng` (12 independent `numpy.random.Generator` substreams derived from one `SeedSequence`), `ids` (deterministic, sequential, prefixed, non-CPF identifiers), `population`/`applications` (customers, applications, frozen `application_features`, evaluation-only `fairness_attributes`), `policies`/`decisions` (a synthetic decision score computed only from visible features, never the truth layer), `contracts`/`schedules` (booking + `Decimal`-based reducing-balance amortization, residual-cent-safe), `payments` (the month-by-month ledger simulation - the core of the generator), `allocations` (deterministic fees→interest→principal payment allocation), `snapshots` (DPD/bucket/balance derivation from the in-memory ledger), `collections`/`writeoffs`/`recoveries` (event decision and row construction), `macro` (re-expresses real, already-acquired BCB data - never invents a value), `truth` (the physically isolated synthetic-truth layer), `manifest` (canonical, order-independent per-table/config/global content hashing), `writers` (Parquet output, path-traversal-safe atomic staging→promotion), `validation` (contracts-strict + PII-safety + technical statistical checks), and `orchestrator` (`generate_baseline`, tying every step together in causal order).
- Real CLI commands, replacing the Phase 3 stub: `credlens synthetic generate --scenario baseline --scale {smoke,sample,portfolio} --seed N [--force]` (every other scenario is rejected with `ScenarioNotCalibratedError` before any generation runs), `credlens synthetic validate --run-id <id>`, `credlens synthetic inspect --run-id <id>`, `credlens synthetic manifest --run-id <id>` - all path-traversal-safe.
- Reproducibility, proven (not just claimed): the same `(scenario, scale, seed, config)` produces an identical `generation_run_id` and an identical canonical `global_content_hash` across independent runs; a different seed produces a different one - verified via the real CLI (three real generations in this phase's own validation) and via `tests/test_generation_orchestrator.py`.
- Three mandatory Phase 3 conceptual fixes, completed before the generator was built: (1) `macro_context_monthly` row-level provenance (`source_type`/`source_id`/`is_synthetic` columns + `macro_context_provenance_consistent` rule) so real BCB observations and future synthetic shocks can never be silently conflated - see `docs/adr/0008-macro-context-provenance.md`; (2) removal of the Phase 3 fixture's `DPD=999` sentinel, replaced by a `no_snapshot_after_terminal_status` retention rule and a real, ledger-derived DPD, always - see `docs/adr/0009-dpd-sentinel-removal.md`; (3) `account_monthly_snapshots.cumulative_paid`/`total_balance`/`cumulative_write_off`/`dpd` now reconciled against `installments`/`payments`/`payment_allocations`/`write_off_events` via 4 new financial rules, closing the gap Phase 3 explicitly declared open.
- 6 new business-rule functions (22 → 28 total in `registry.KNOWN_BUSINESS_RULE_CODES`): `macro_context_provenance_consistent`, `no_snapshot_after_terminal_status`, `snapshot_cumulative_paid_reconciled`, `snapshot_balance_reconciled_with_ledger`, `snapshot_write_off_reconciled`, `snapshot_dpd_reconciled_with_installments`.
- `credlens.contracts.validators` now dispatches file reads by the file's own extension (supporting Parquet) rather than solely by the contract's declared `format`, so the same 20 contracts validate both hand-authored CSV fixtures and real generated Parquet output without a schema change.
- The `baseline` scenario blueprint (`config/synthetic/scenarios/baseline.blueprint.yaml`) now has concrete, documented synthetic-assumption parameter values (status `synthetic_assumptions_specified`, a new `BlueprintStatus`) mirroring the executable config; every other scenario remains `requires_calibration`.
- 6 real bugs found and fixed while building and testing this phase's own generator (documented transparently in `docs/synthetic_generation_implementation.md`): an `ALLOCATION_EXCEEDS_PAYMENT` false positive from a missing floating-point tolerance, empty-result tables losing their column schema, a `pd.merge_asof` dtype mismatch on all-empty ledger inputs, a missing `due_date < snapshot_date` filter in the ledger reconciliation, a cross-month payment-reversal bug that broke reproducibility (caught by the determinism proof itself), and `credlens synthetic validate` silently skipping non-`synthetic_operational` tables.
- 135 new tests (524 total) covering the full generation package (RNG substream independence, id determinism and non-CPF shape, feature-freeze and fairness-attribute separation, decision-score/truth-layer separation, amortization rounding and reconciliation, deterministic payment allocation, DPD/bucket derivation, the terminal-status retention rule, canonical hashing determinism, atomic staging/promotion, path-traversal protection, statistical/PII validation, and full end-to-end generation runs validated against the real `credlens.contracts` strict-mode code path at multiple seeds and scales), plus updated CLI tests for `synthetic generate/validate/inspect/manifest`.
- New dependencies: `numpy` (reproducible RNG substreams) and `pyarrow` (Parquet read/write) - justified in `pyproject.toml`; no modeling library (scikit-learn, XGBoost, LightGBM, SHAP) or synthetic-data library (Faker) was added.
- New documentation: `docs/synthetic_generation_implementation.md` (the as-built generator design and its own real-bug log), `docs/adr/0008-macro-context-provenance.md`, `docs/adr/0009-dpd-sentinel-removal.md`; cross-references updated across `docs/synthetic_generation_spec.md`, `docs/data_contracts.md`, `docs/business_rules.md`, `docs/metric_semantics.md`, `docs/architecture.md`, `docs/assumptions_and_limitations.md`, `docs/roadmap.md`, `data/README.md`, and both READMEs.
- A real sample-scale (5,000 customers) generation was run manually for this phase's own validation (~57s, 101,383 total rows, all contracts/PII/statistical checks passing) - not part of the automated test suite, and `portfolio` scale (50,000 customers) was not executed at all in this phase, per its explicit scope.

### Explicitly not included in this phase

No scenario other than `baseline` (`policy_expansion`, `policy_tightening`, `macroeconomic_stress`, `collections_change`, `data_quality_incident` all remain unimplemented and rejected), no calibration against any real-world statistic, no warehouse, no SQL analytics, no risk model, no dashboard, no business recommendation, and no commits or pushes. See `docs/roadmap.md` for what each of these becomes in later phases.

## [0.3.0] - 2026-07-24

### Added — Conceptual modeling, temporal semantics, and data contracts phase

- Conceptual data model: 17 entities (customers, applications, application_features, fairness_attributes, policy_versions, credit_decisions, contracts, installments, payments, payment_allocations, account_monthly_snapshots, collection_events, write_off_events, recovery_events, macro_context_monthly, generation_runs) plus a specified-but-not-built "synthetic truth" layer, modeled as a hybrid of events, current state, and snapshots (never one undifferentiated table) across 4 Mermaid ER diagrams. See `docs/conceptual_data_model.md`.
- `docs/temporal_semantics.md`: formal roles for every timestamp/date family (`event_timestamp`, `effective_from`/`effective_to`, `snapshot_date`, `due_date`, `payment_date`, `settlement_date`, `write_off_date`, `as_of_date`, `ingested_at`, `generated_at`), a causal ordering chain, and documented valid exceptions.
- `docs/state_machines.md`: reviewed (not blindly accepted) state machines for applications, contracts, and installments, with an explicit table of what is/isn't mechanically enforced.
- `docs/metric_semantics.md`: a project-specific (not regulatory) DPD bucket convention, and an explicitly *unconfigured* "Default" definition (threshold/window/write-off treatment all left `unset`, versioned for a future phase to actually decide).
- `src/credlens/contracts` package: `models` (Pydantic schema for contract YAML metadata), `loader`, `registry` (cross-reference validation, known-business-rule-code registry), `validators` (audit/strict dispatch, single-file and scenario-directory modes), `domain_rules` (vectorized PK/FK/domain/nullability/CPF-pattern checks), `relational_rules`/`temporal_rules`/`financial_rules` (22 named, vectorized, cross-table business rules), `reporting` (`Finding`/`ValidationReport`, stable error codes).
- 20 data contracts: `contracts/raw/*.yaml` (4, covering the Phase 2 public sources) and `contracts/operational/*.yaml` (16, covering the not-yet-built synthetic operational layer) - each with grain, PK, FKs, typed/domain-constrained columns, uniqueness rules, and named business rules.
- Two validation modes on `credlens contracts validate`: `audit` (diagnostic, never fails the command - for the immutable public sources) and `strict` (fails on any error finding - for the future synthetic layer and its test fixtures). See `docs/adr/0006-audit-vs-strict-validation.md`.
- Automated the two pieces of Phase 2 technical debt this phase was required to close: UCI EDUCATION/MARRIAGE out-of-domain code detection (previously a one-off manual script; now the `uci_default_credit` contract's declared domains, reproducing the same 345/54 violation counts) and BCB observation-date uniqueness/ordering (previously a manual re-check after the chunking-boundary bug fix; now the `data` primary key plus the `bcb_dates_strictly_increasing` business rule) - both with permanent regression tests.
- `docs/synthetic_generation_spec.md` and `config/synthetic/*.blueprint.yaml` (6 named scenarios: baseline, policy_expansion, policy_tightening, macroeconomic_stress, collections_change, data_quality_incident) - a specification and structurally-validated blueprints only, with every parameter honestly marked `pending`/`requires_calibration` (never a fabricated real-world value) and a "known truth" section for a future generator's own validation. No synthetic data is generated.
- CLI additions, all existing commands preserved: `credlens contracts list|show|validate`, `credlens synthetic plan|scenarios|validate-blueprints`, and `credlens synthetic generate` (which deliberately prints "Not implemented: scheduled for the synthetic generation phase." and exits 1 - no data is produced).
- 7 ADRs (`docs/adr/0001`-`0007`): foreign-vs-Brazilian-context separation, adoption of a synthetic operational layer, hybrid events/state/snapshots architecture, feature freeze at the proposal instant, fairness-attribute physical separation, audit-vs-strict validation modes, and synthetic-truth isolation.
- `tests/fixtures/contracts/`: one small, coherent `valid_minimal_scenario` (passes all 16 operational contracts in strict mode with zero findings) plus 11 purpose-built invalid scenarios (PK duplicate, FK orphan, invalid domain, causally impossible date, approval without a valid policy, contract from a rejected application, payment exceeding its allocation, cross-contract allocation, incompatible DPD/bucket, duplicate snapshot, recovery before write-off) - each verified to fail with its exact intended finding code.
- 228 new tests (369 total) covering the contracts package (models/loader/registry/validators/domain_rules/relational_rules/temporal_rules/financial_rules/reporting), `credlens.synthetic`, both new CLI command groups, the full fixture suite end-to-end, and dedicated regressions for the EDUCATION/MARRIAGE automation, BCB date uniqueness/chunking, the timezone-comparison bug found and fixed this phase, and CPF-shaped identifier detection.
- New dependency: `pydantic` (contract/blueprint metadata parsing only - table data validation stays vectorized pandas, never per-row). See `docs/adr/0006-audit-vs-strict-validation.md` and the rationale comment in `pyproject.toml`.
- 4 real bugs found and fixed during this phase's own construction, documented transparently in `docs/data_contracts.md`: a timezone-naive/aware comparison crash, a type-mismatch false positive on `macro_context_monthly.series_code`, a missing foreign-key data check, and a synthetic-truth field that had been misplaced directly on an operational table (caught before merge, not after).

### Explicitly not included in this phase

No synthetic data generation (the generator, blueprints' calibration, and `credlens synthetic generate`'s actual implementation are explicitly deferred), no dbt models, no SQL warehouse, no KPI computation, no risk model, no policy simulator, no dashboard, no changes to any raw file under `data/raw/`, and no commits or pushes. See `docs/roadmap.md` for what each of these becomes in later phases.

## [0.2.0] - 2026-07-23

### Added — Data acquisition, provenance, and audit phase

- `credlens.data` package: `models` (typed source/manifest/download records), `registry` (loads/validates `data/metadata/source_registry.yaml`, checks status-evidence coherence), `downloader` (idempotent HTTP acquisition with retries, atomic writes, path-traversal protection, safe zip extraction), `bcb_client` (Banco Central do Brasil SGS time-series client with explicit date ranges and window chunking), `checksums` (SHA-256), `manifest` (deterministic `data/metadata/file_manifest.csv` read/write/verify), `schema` (documented-column comparison), `profiler` (structural DataFrame profiling), `audit` (categorized findings: confirmed problem / candidate anomaly / documented characteristic / hypothesis requiring investigation / structural limitation).
- CLI: `credlens data sources`, `credlens data fetch --source <id>`, `credlens data verify`, `credlens data audit`; `credlens doctor` now reports registered data-source counts as an informational check.
- Real, reproducible acquisition of 4 of 5 registered sources this session: `uci-default-credit` (Default of Credit Card Clients, UCI, CC BY 4.0), `south-german-credit` (South German Credit, UCI, CC BY 4.0), `bcb-sgs-20570` and `bcb-sgs-21112` (Banco Central do Brasil SGS series, ODbL). `home-credit` (Kaggle) registered as `BLOCKED_REQUIRES_USER_ACCESS` with documented evidence, per this project's rule against embedding or requesting credentials.
- A real bug caught by this project's own audit tooling and fixed during acquisition: BCB SGS date-window chunking produced one duplicate observation per series at a chunk boundary (month-inclusive date semantics); fixed in `credlens.data.bcb_client` with a targeted, order-preserving deduplication that only removes byte-for-byte identical repeats.
- New documentation: `docs/dataset_selection.md` (weighted decision matrix + sensitivity analysis), `docs/data_sources.md`, `docs/data_licensing.md`, `docs/data_dictionary.md`, `docs/data_quality_audit.md`, `docs/target_and_leakage_audit.md`, `docs/sensitive_attributes.md`.
- New dependencies: `requests` (HTTP), `pandas` (tabular reading + audit statistics), dev-only `responses` (HTTP mocking in tests) and `pandas-stubs`/`types-requests` (mypy strict compliance).
- `config/base.yaml` gained an optional `data:` section (HTTP timeout/retries, BCB query defaults) - purely structural, no credentials, no business thresholds.
- 76 new tests (141 total) covering the full data-acquisition layer, including HTTP-mocked downloader/BCB-client edge cases (timeouts, retries, 4xx/5xx, partial-file safety, overwrite protection, path traversal), manifest determinism, schema/profiler/audit logic, and CLI end-to-end flows sandboxed away from real files.

### Explicitly not included in this phase

No analytical cleaning or transformation of raw data, no dimensional modeling, no SQL warehouse, no synthetic data generation, no model training, no PD/score calculation, no policy simulation, no dashboard, and no commits or pushes. See `docs/roadmap.md` for what each of these becomes in later phases.

## [0.1.0] - 2026-07-23

### Added — Foundation phase

- Project scaffolding: `src`-layout Python package (`credlens`), `pyproject.toml` with dependency, lint, type-check, and test configuration, and a `uv.lock` reproducible lockfile.
- Minimal CLI (`credlens` / `python -m credlens`) with `--help`, `version`, and `doctor` commands, the last verifying only foundation-phase concerns (Python version, package version, config file, required directories) and explicitly not treating an absent dataset as a failure.
- Centralized configuration loading and validation (`credlens.config`) reading `config/base.yaml`, with clear errors for missing files, invalid YAML, and schema violations.
- Structured logging setup (`credlens.logging_config`).
- Pytest suite covering package import/version, all three CLI commands (including the `python -m credlens` entry point), and configuration loading's success and error paths.
- Ruff (lint + format), MyPy (strict), and Pytest-cov wired into local development and GitHub Actions CI.
- Business and architecture documentation: project charter, business problem framing, stakeholder map, preliminary KPI dictionary, data strategy, target architecture, assumptions & limitations, glossary, and phased roadmap.
- `README.md` and `README.pt-BR.md`, `LICENSE` (MIT), `CONTRIBUTING.md`, `SECURITY.md`, and GitHub issue/PR templates.

### Explicitly not included in this phase

No data acquisition, no ETL, no SQL warehouse, no dbt models, no exploratory analysis, no computed KPI values, no risk model, no policy simulator, no Power BI dashboard, no demo application, no Docker, and no claimed business results. See `docs/roadmap.md` for what each of these becomes in later phases.
