# CredLens Dashboard (Phase 7)

A Streamlit **presentation layer** over the already-validated CredLens warehouse/analysis
outputs. No business rule is computed here — every KPI comes from a dbt mart
(`warehouse/models/marts/*.sql`) queried through `credlens.analysis.metrics`/`scenarios`, every
sample-size label comes from `credlens.analysis.sample_policy`, every provenance label comes
from `credlens.analysis.data_provenance`. The dashboard's own code (`src/credlens/dashboard/`)
only loads, filters, formats, and renders.

## Quick start

```bash
uv sync --extra warehouse --extra analysis --extra dashboard

# Demo mode - no data/warehouse/ needed at all
uv run credlens dashboard run --demo

# Validated-warehouse mode - needs a real build
uv run credlens warehouse build --suite-id SUITE_sample_2026
uv run credlens analysis run --build-id <build_id> --insights
uv run credlens dashboard run --build-id <build_id>
```

## Architecture

```text
dashboard/                         # Streamlit scripts (not part of the installable package)
├── app.py                         # Entry point: resolves/validates the data source once,
│                                   # then routes to a page via st.navigation
├── pages/
│   ├── 1_Executive_Overview.py
│   ├── 2_Credit_Funnel.py
│   ├── 3_Portfolio_Delinquency.py
│   ├── 4_Vintages_Roll_Rates.py
│   ├── 5_Cure_Collections_Recovery.py
│   ├── 6_Scenario_Lab.py
│   ├── 7_Data_Quality_Methodology.py
│   └── 8_Public_Benchmarks.py
├── demo_data/                     # Generated by `credlens dashboard export-demo` - versioned,
│                                   # small (see "Demo package" below)
└── assets/                        # Static assets for docs/README

src/credlens/dashboard/            # Installable, testable support package
├── config.py                      # Mode resolution (warehouse vs demo), no path traversal
├── bootstrap.py                   # CLI-arg / env-var resolution used by every page script
├── validation.py                  # Pre-flight: refuses a failed build / mutated source /
│                                   # tampered demo package before any data is shown
├── data_access.py                 # Cached, read-only access to marts (warehouse) or Parquet
│                                   # (demo) - one unified `DashboardData` shape
├── filters.py                     # Filter option derivation + application (never raises)
├── queries.py                     # Display reshaping only (latest snapshot, totals) - no
│                                   # new business logic
├── sample_policy (reused)         # credlens.analysis.sample_policy - insufficient/limited/
│                                   # adequate classification
├── provenance.py                  # Page-level provenance category declarations
├── components.py                  # KPI cards, sample-size badges, empty states, mode badge
├── charts.py                      # Plotly chart builders (interactive, consistent colours)
├── exports.py                     # CSV/PNG export with a provenance metadata sidecar
├── demo_package.py                # Builds/validates the small aggregate demo package
└── pages.py                       # The actual page composition logic (unit-testable
                                    # independently of the Streamlit `pages/*.py` scripts)
```

## Page dictionary

| Page | Provenance | Content |
|---|---|---|
| Executive Overview | synthetic_scenario | Period, scenario, applications, approval/booking rate, active contracts, outstanding balance, PAR30/90, cure rate, validated insights summary |
| Credit Funnel | synthetic_scenario | Submitted→decisioned→approved→booked, by channel/policy version/product/bureau-score/income/contract-value band, baseline vs. expansion/tightening |
| Portfolio & Delinquency | synthetic_scenario | Outstanding balance, active contracts, ticket, scheduled amount, paid-to-scheduled ratio, DPD buckets, PAR30/60/90 |
| Vintages & Roll Rates | synthetic_scenario | Cohort/MOB selection, 90+ incidence curves (comparable-MOB only), roll-rate heatmap, roll-forward rate |
| Cure, Collections & Recovery | synthetic_scenario | New delinquencies/cures/relapses, redefault rate, collections activity (with its causal-limitation warning), write-off/recovery totals and rate |
| Scenario Lab | synthetic_scenario | Baseline vs. every scenario, composition-vs-performance, pre/post-shock, multi-seed variability (never a confidence interval) |
| Data Quality & Methodology | synthetic_operational | Build/analysis/fingerprint, full provenance registry, documentation links, limitations |
| Public Benchmarks | mixed_context | UCI / South German Credit / BCB SGS — real public data, visually separate, empty state if unavailable |

## Filter dictionary

Scenario, channel, product, region, policy version, bureau score bucket, income band (quartile),
contract value band (quartile), cohort (vintage month), DPD bucket, date range. A filter whose
column does not exist on a given table is simply not applied to that table (never raises); an
empty match renders an explicit empty state, never an error. Selections persist across page
navigation within one browser session.

## Formatting rules

Synthetic monetary amounts are **never** labeled `R$` — they use the explicit "synthetic
monetary units" convention (`credlens.dashboard.formatting.format_synthetic_money`). Public
benchmark values use that source's own declared unit. NaN/Infinity are always rendered as `n/a`,
never as literal text, never raising.

## Provenance

Every table/figure/page declares one of `synthetic_operational`, `synthetic_scenario`,
`public_benchmark`, `public_market_context`, `mixed_context` (`credlens.analysis.data_provenance`
— the single registry the analysis reports, this dashboard, and the demo package all read).

## Demo package

`credlens dashboard export-demo --build-id <BUILD_ID>` builds `dashboard/demo_data/` from an
already-validated `credlens analysis run` output directory: Parquet copies of every aggregate
table the dashboard needs, plus `insights.yml` and a `manifest.json` (hashes, row counts, source
build id, provenance, size). `cure_and_redefault` (the one table whose native grain is one row
per contract) is re-aggregated into a scenario-level summary before inclusion — **no
customer/contract-level row ever leaves this package**. Size budget:
`credlens.dashboard.demo_package.DEMO_PACKAGE_SIZE_BUDGET_BYTES` (5 MiB); the actual package
built from this repository's own official build was ~190 KB.

## Modes

The dashboard supports exactly two modes, always shown in the sidebar:

- **Validated warehouse mode** (`--build-id <BUILD_ID>`): re-validates the build (dbt tests,
  raw-source integrity) via the same gate `credlens analysis run` uses, then queries it
  read-only.
- **Demo aggregate mode** (`--demo`): reads the versioned Parquet package, tamper-checked via
  its own manifest hashes. No `data/warehouse/` access at all.

## CLI

```bash
credlens dashboard validate --build-id <BUILD_ID>   # or --demo
credlens dashboard export-demo --build-id <BUILD_ID>
credlens dashboard run --build-id <BUILD_ID>         # or --demo
credlens dashboard run --demo --port 8600 --no-browser
credlens dashboard status
```

## Troubleshooting

- **"Both a demo package and at least one warehouse build are available"**: pass `--build-id`
  or `--demo` explicitly — the dashboard never silently picks one for you.
- **"Build 'X' failed raw source integrity verification"**: a raw parquet file changed since
  that build ran — rebuild (`credlens warehouse build`) or use a different build.
- **"Demo table 'X' failed integrity verification"**: the demo package was modified after
  generation — regenerate it with `credlens dashboard export-demo`.
- **Streamlit port already in use**: pass `--port <N>`.

## Limitations

- Time-to-cure is not computed in this build (would need a dedicated day-count calculation not
  yet in the warehouse layer) — stated on the Cure, Collections & Recovery page, not silently
  omitted.
- `collections_change` results are never causal evidence for an individual collections action.
- Scenario comparisons are only valid within the same `suite_id`.
- No revenue/cost/LGD/EAD/regulatory PD data exists anywhere in this project.
- No pixel-level visual QA (contrast, clipping, tooltips) was performed in the environment this
  dashboard was built in — no browser automation tool was available; verification instead used
  `streamlit.testing.v1.AppTest` (every page, both modes) plus a real, running server checked
  over HTTP (`/_stcore/health`).
