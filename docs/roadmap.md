# Roadmap

An incremental phase plan. Each phase lists its dependency on prior phases and the criteria that would mark it complete — no dates are assigned, since forcing arbitrary deadlines onto a portfolio project would be as fabricated as an invented metric. Note: the project's own session-level "Phase 5" (delinquency-semantics correction + analytical warehouse) delivered this table's rows 5, 6, most of 7, and most of 8 together, in one pass - see `docs/warehouse_architecture.md` and the Phase 5 final report for the as-delivered scope. The session-level "Phase 6" (Credit Portfolio Intelligence) closed out row 7's remaining `proposed` KPIs, hardened three warehouse-integrity gaps found by re-reading Phase 5's own documentation against its code (monetary reconciliation tolerance, test-root isolation, raw-source mutability - see `docs/warehouse_architecture.md`'s Testing strategy section), and added a reproducible analysis/reporting layer on top of rows 6-8 (`credlens.analysis`, a versioned business-question registry, bilingual executive/technical reports, a case-study notebook) - see `docs/analysis_architecture.md` and the Phase 6 final report. The session-level "Phase 7" (Decision Intelligence Dashboard) closed the analytical gaps Phase 6 left open (multi-seed robustness for all four scenarios, a three-tier sample-size policy, five-category data provenance, a generated insights registry, a reproducibility fingerprint covering reports/insights, a Jupyter-kernel-executed notebook), then delivered row 13 below (a Streamlit demonstration application reading the warehouse marts, with a versioned demo package) - see `dashboard/README.md` and the Phase 7 final report. Row 12 (Power BI specifically) remains open, and the session-level "Phase 10" (1.0 Release Candidate) formally closed it as won't-do rather than leaving it a live future item: Phase 7 satisfied the underlying need with Streamlit rather than a Microsoft BI tool, a deliberate substitution, and Phase 10's own scope explicitly excludes ever adding a Power BI layer - see `README.md`'s "What is out of scope by design" section. Row 12's literal completion criteria below are kept for historical traceability only. The session-level "Phase 8" (Interpretable Behavioral Credit Risk Modeling) delivered row 10 ahead of its formal dependencies (rows 7 and 9): rather than a PD model on the warehouse's synthetic data requiring an expected-loss calculation that does not exist, Phase 8 trained and validated a **behavioral early-warning model on the real, public UCI benchmark** - deliberately never on the synthetic portfolio, and deliberately never with a profit/cutoff optimization row 9/11 would require. See `reports/modeling/technical_report.md` and the Phase 8 final report. The session-level "Phase 9" (Independent Model Validation, Monitoring Simulation and Model Risk Governance) is not itself one of this table's 17 rows (the original plan did not anticipate a dedicated model-risk-governance phase) - it deepens row 10's own validation rigor instead: an independent recomputation of Phase 8's evidence (never copying its numbers), a permutation-based negative control replacing a fragile fixed-band shuffle check, a multicollinearity audit, corrected subgroup gap definitions, a formally registered `challenger` model, and a clearly labeled monitoring SIMULATION (never a real production monitoring system) over the same public benchmark. See `reports/model_validation/validation_report.md`, `reports/monitoring/monitoring_report.md`, and the Phase 9 final report.

## How this roadmap is meant to be used

- A phase does not start until its dependencies are marked complete against the criteria above — not against a subjective sense of "good enough."
- Completing a phase means updating this table's row (and any linked documents) to reflect reality, not marking it done in advance of the work.
- Phases 7 onward will very likely surface the need for the "requires_validation" KPIs in `docs/kpi_dictionary.md` to be revised. That is expected and welcome — the dictionary is preliminary by design.
