# Portfolio Analysis Output (Phase 6)

Generated by `credlens analysis run` - never hand-edited. Everything here
describes a fully synthetic data-generation process (DGP), not a real
financial institution.

## Contents

- `executive_summary.md` / `executive_summary.pt-BR.md` - short, decision-card-based summary (EN/PT-BR).
- `technical_report.md` / `technical_report.pt-BR.md` - full analytical architecture, SQL provenance, validations, limitations (EN/PT-BR).
- `tables/*.csv` - every query result the analysis run produced, one file per named query in `src/credlens/analysis/metrics.py`/`scenarios.py`.
- `figures/*.png` - every chart `src/credlens/analysis/charts.py` generated from the tables above.
- `manifest.json` - provenance: build id, warehouse fingerprint, source hashes, versions, query/table/figure hashes, parameters, warnings, final status (Phase 6 section 18).

## Regenerating this directory

```bash
uv sync --extra warehouse --extra analysis
uv run credlens warehouse build --suite-id SUITE_sample_2026
uv run credlens analysis run --build-id <build_id> --force
```

Add `--multiseed` to also run a real multi-seed robustness sweep (see the
technical report's "Multi-seed robustness" section) - this performs real
data generation and is not run by default or in CI.

## Reproducibility

`credlens analysis reproduce --output-dir reports/portfolio_analysis` re-runs
the same build_id into a separate directory and verifies every table/figure
content hash matches exactly - the proof that this output is deterministic,
not a one-off.
