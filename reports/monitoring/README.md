# Monitoring Simulation Output (Phase 9)

Generated by `credlens monitor {create-reference,simulate-batches,run,status,alerts,report,
validate}` - never hand-edited. **"Monitoring simulation on a historical public benchmark"** -
never a real production monitoring system. Batches are simulated, non-overlapping partitions of
the UCI benchmark's own locked test set (Phase 8), sliced by ID - never real dated production data.

## Contents

- `reference/<reference_id>.json` - the monitoring reference (train+validation only, never the
  locked test set): per-feature mean/median/std/quantiles/histogram, score distribution, risk-band
  distribution, subgroup composition.
- `reference/<reference_id>__population.csv` - **git-ignored**: the full train+validation
  engineered-feature + score + sensitive-attribute table used to bootstrap-calibrate alert
  thresholds - never used to retune the model.
- `reference/<reference_id>__alert_thresholds.json` - calibrated `review`/`material_deviation`
  cutoffs per metric, derived from the reference's OWN bootstrap resampling - never a copied
  market-generic PSI/KS band.
- `runs/<batch_set_id>/batches/batch_NN.csv` + `batch_manifest.json` - the 12 simulated batches
  (`batch_sequence`, `simulation_scenario`, `source_partition`, `label_availability`).
- `runs/<run_id>/run.json` - the full per-batch result: data quality, feature drift (PSI/KS/
  Wasserstein/Jensen-Shannon/mean-median-variance-quantile shift/missingness delta), score drift,
  performance drift (only when `label_availability="available"`), subgroup monitoring.
- `alerts/<run_id>.json` - local, structured alerts only (`alert_id`, category, metric, reference/
  observed value, threshold, severity, recommended diagnostic action, status) - **never emailed,
  never posted to Slack/a webhook, never acted on automatically**.
- `monitoring_report.md` / `monitoring_report.pt-BR.md` + `manifest.json` - the bilingual report
  (batches, alerts, false-alert rate on the unperturbed `baseline_like` batch).

## Regenerating this directory

```bash
uv run credlens monitor create-reference --model-id MODEL_behavioral_default_v1
uv run credlens monitor simulate-batches --reference-id REF_MODEL_behavioral_default_v1
uv run credlens monitor run --reference-id REF_MODEL_behavioral_default_v1 \
  --batch-set BATCHSET_REF_MODEL_behavioral_default_v1
uv run credlens monitor report --run-id <RUN_ID printed above>
uv run credlens monitor validate --run-id <RUN_ID>
```

`create-reference`/`simulate-batches` refuse to silently overwrite an existing reference/batch
set - use a different `--model-id` (which changes the derived `reference_id`) to build a second one.

## The 12 simulated batches

`baseline_like` (false-alert-rate control) / `missingness_drift` / `utilization_shift` /
`payment_reduction` / `delinquency_worsening` / `out_of_domain_codes` / `feature_range_violation`
/ `prevalence_drift` / `score_distribution_shift` / `subgroup_composition_shift` / `label_delay`
(performance intentionally marked `labels_pending`) / `corrupted_schema` (intentionally rejected
by `credlens.modeling.input_contract`'s strict mode - `blocked_input`, never scored).

## Scope boundaries

- No real production timeline, no real dated batches.
- Alert thresholds are a demonstration, not institutional limits.
- No automatic remediation, no automatic retraining, no automatic promotion.
- Sensitive attributes (SEX/EDUCATION/MARRIAGE) are joined only for post-hoc subgroup monitoring,
  never a model input, never used to adjust a threshold per group.
