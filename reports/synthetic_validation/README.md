# Synthetic validation reports (Phase 4B)

Technical, aggregate-only reports produced by the Phase 4B counterfactual-scenario
and performance work. None of these files contain individual-level data (no
customer/application/contract rows) - only counts, hashes, config diffs, and
aggregate rates. See `docs/counterfactual_scenarios.md`,
`docs/common_random_numbers.md`, and `docs/performance_optimization.md` for the
narrative behind these numbers.

| File | What it contains | How it was produced |
| --- | --- | --- |
| `performance_baseline.json` | Sample-scale generation time/hash measured with the pre-optimization (Phase 4A) generator code, re-measured on this machine for a fair comparison. | `git stash` the Phase 4B performance changes, run `credlens synthetic generate --scenario baseline --scale sample --seed 2026`, read `manifest.json`. |
| `performance_optimized.json` | The same measurement with the optimized code, plus a list of the 4 optimizations applied and what was identified but deliberately not touched. | Same command, current code. |
| `scenario_suite_summary.json` | Per-scenario config diff keys, CRN preservation flag, and baseline/scenario aggregate metrics for one suite (seed 2026, scale smoke). | `credlens synthetic generate-suite --scale smoke --seed 2026`. |
| `directional_tests.json` | The invariant checks (superset/subset, pre-shock identity, ...) and metric deltas for that same suite. | Same suite run; this is a narrower view of `suites/SUITE_smoke_2026.json`. |
| `monte_carlo_summary.json` | 10-seed Monte Carlo comparison of `macroeconomic_stress` vs. baseline: mean/stdev/quantiles per metric delta, and the fraction of seeds where DPD90+ increased. | `credlens synthetic monte-carlo --scenario macroeconomic_stress --scale smoke --seeds 10`. |
| `contract_coverage.json` | Which of the 13 states `contract_coverage` was designed to force were actually observed in a real run, plus the one documented, architectural gap (delinquency relapse). | `credlens synthetic generate --scenario contract_coverage --scale smoke --seed 2026`, then inspecting the real output tables. |
| `suites/SUITE_<scale>_<seed>.json` | The full suite manifest `credlens synthetic generate-suite` writes: run ids, config diffs, population hashes, metrics, and directional checks for every scenario in the suite. | Written automatically by `generate_suite()`. |

All of the above are regenerated by re-running the commands in the "How it was
produced" column - nothing here is hand-edited after generation, other than this
README and the two `performance_*.json` files' one-line contextual `note` field.
